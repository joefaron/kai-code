what we built

Four projects. One helper.

  • Airboat — recycled bottles, two fans, steered from a tablet over its own Wi‑Fi
  • Paper plane — about 21 g, two tiny motors, steers with no rudder at all
  • Game console — a pocket computer that plays games you invent
  • 3D‑printed parts — a shaft coupler and motor holders, designed by typing

The helper is an AI we call Bugsy. We talk to it in a chat app, like texting.

This is the one big idea of the talk. A language model was trained on a huge pile of text and learned which word tends to come next. It doesn't "know" things like you do - it predicts. the one skill: prompting

A great prompt has 4 parts

1. GoalWhat do you want to exist when it's done?
2. ContextWho it's for, what you already have
3. LimitsBudget, size, "no soldering", your grade
4. CheckHow will we KNOW it worked?
weakmake me a boat
strongPlan a boat for a 6th-grade race (goal). We have bottles and an ESP32 (context). Under $50, nothing underwater (limits). Tell me how we'll test it floats before race day (check).
Read the weak one, then the strong one. Point out each colour. The 4th part - CHECK - is the one adults forget. If you ask the AI how to check its own work, it catches its own mistakes. We'll see that on every slide.

prompt #1 · build a website

The first message built the whole site

we typed"Make a new website for my son's 6th grade project. Teach him about an Arduino microcontroller, set up so a tablet can control the motor and the direction. It needs to be waterproof. I'm not sure how much this costs."
ai builtThe mission, a design (an airboat, so nothing underwater can leak), a parts list with prices, a touch‑screen helm with a boat simulator, and the chip's code.
then we said"You need to actually test how this steering works."

It measured instead of guessing — and found the bug: the simulator ran once per screen refresh, and Dad's screen refreshes 161 times a second.

The site you're seeing in 3D is real: this project's own website. One message got a first version. The magic was the second message: "actually test it". The AI drove a real browser, measured, and found a bug that only happened on a fast monitor. Lesson: the first answer is a draft.

prompt #2 · design a 3D-printed part

"Make me a coupler"

we typed"Design a coupler that joins a 2 mm motor shaft to a 2 mm steel prop rod. It should print standing up with no supports, and be a tight press fit — no glue. Give me the OpenSCAD file."
  1. AI wrote code that describes the shape: bore_motor = 2.2;
  2. Printed it. Both shafts slid straight through.
  3. Asked why. On this printer holes come out true size, so a tight fit needs a hole smaller than the shaft.
  4. Changed one number to 1.9 — and printed a test strip with holes 1.7 → 2.1 first.

The real world beats the math. Print a small test first.

The spinning part is the real coupler file, loaded from the STL we printed. OpenSCAD is "code that makes shapes" - so a one-number change gives a new part. Show 3d/shaft_coupler.scad on GitHub if there's time. Good prompt words for 3D printing: the exact sizes in mm, how it prints (standing up, no supports), and how it attaches (press fit, screw, glue).

prompt #3 · shop smart

Have it research the parts — then check its homework

we typed"Research what to buy on Amazon for a Wi‑Fi paper plane. Check what I already ordered first. Bare minimum, no soldering. For every listing, read what's in the box and the weight."
  • A battery listing showed 5 batteries in the photo. The box had a charger and zero batteries. The weight (22 g) gave it away.
  • "Rechargeable AA" batteries are 1.2 V, not 1.5 V — too weak for the boat's brain. A USB power bank we already owned fixed it for $0.
  • Then: "adversary-review the shopping cart." It found its own two mistakes.

Every gram counts: the plane can only lift ~25 g.

The tower on the right is the plane's weight budget - each block is a real part. "Adversary-review" means: pretend you're the person trying to prove this is wrong. It's the most useful phrase in this whole talk. The AI never buys anything. It puts things in a cart; a grown-up checks out.

the schematic

Brain → muscle → motors

  • Brain: XIAO ESP32‑C3 — a computer smaller than a stamp, with Wi‑Fi
  • Muscle: DRV8833 motor driver. The brain's pins are too weak to spin a motor; the driver does the heavy lifting.
  • Motors: spin the left one faster and the plane turns right. No rudder.
  • Power: one tiny battery, split two ways.

Every wire here is drawn from one file of pin numbers. Change a pin there and the website, the booklet and the 3D all update.

This 3D wiring is generated live from data/plane.json - the same file the printable booklet uses. Point at a glowing wire: those pulses are signals going from the brain to the driver. Lesson from the real build: we trust the labels printed on the chip over ANY drawing, including the AI's.

prompt #4 · flash the code

Getting code onto the chip

we typed"I just plugged it into my USB. Find the ESP32 and figure it out."
  1. Windows couldn't see it — a driver was missing for the board's USB chip. AI installed it.
  2. It compiled the code (turned it into chip language) and uploaded it.
  3. Upload failed? Try another USB port. Once it took 6 tries, then a port swap.
  4. Now it updates over Wi‑Fi. No cable — and a password so nobody else can.

Short prompts work when the AI can see the problem itself.

"Flashing" = copying a program into the chip's memory so it runs on its own. The cable-free version is called OTA (over the air). The chip only switches to the new code once the whole file arrives, so a dropped connection can't break it.

test before you flash

Your game gets tested on the computer first

  • The game is one file, game.c. Same file runs on the PC and on the console.
  • A robot "player" presses buttons in a script and plays it 3 ways.
  • It checks the rules: "a player who chases pumpkins scores", "a player who does nothing loses 3 lives".
  • Only when every check passes do we put it on the device.

Invent the rules in words. The AI codes it. The test proves it.

The screen on the console is a real screenshot from our test run of "Pumpkin Catch". Kai designs a game in plain words - "pumpkins fall, catch them, three lives" - and the AI writes the C code and a test that plays it.

physics check

Will it actually fly?

  • The balance point (CG) has to sit in front of the wing's lift point (NP), or the plane flips.
  • Ours: CG at 100 mm from the nose, NP at about 121 mm. Good.
  • The AI's first wing shape had never flown. Dad asked "where did this shape come from?" It admitted it had guessed.
  • New rule: tape 5 nickels to a plain paper version and glide it before adding electronics.

Ask "how do you know?" — it's allowed to say "I don't."

Watch the props: when the left motor speeds up, the plane yaws right. That's differential thrust - no servos, no rudder, which saves weight. The nickel test costs 25 cents and answers "can this shape carry the weight?" before we risk any parts.

real mistakes the AI made

You are the critic.

  • Drew a picture with misspelled labels
  • Drew a board the wrong size, with the USB plug in the wrong place
  • Trusted a listing photo over the actual box
  • Made wiring diagrams that were confusing — so we asked for a pin‑by‑pin list instead

Every one was caught by a human asking a question, or a test.

This slide matters. AI is not magic and it is not always right. The fix for every mistake here was the same: look at the real thing (the chip, the box, the print) and tell the AI what you see.

builder rules

Stay safe. Stay honest.

  • Batteries: an adult charges LiPos, on a hard surface. A puffy battery goes in the bin, never in a plane.
  • Soldering: hot! Wash hands after, no snacks at the bench.
  • Privacy: never type passwords, your address or your school into an AI.
  • Age rules: many AI apps are 13+ or need a parent's account. Build with a grown-up.
  • Honesty: if AI helped with schoolwork, say so. Follow your teacher's rules.
Keep this one serious but quick. The shield animation is the "safety" scene. If the school has an AI policy, mention it here.
